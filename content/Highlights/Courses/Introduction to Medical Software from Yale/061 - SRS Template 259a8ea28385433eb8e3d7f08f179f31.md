[[How to write SRS for medical software]] 

# introduction

- Goals and objectives: what is the problem we are trying to solve
- statement of scope
- definitions key terms
- references - list key documents
- significance.
    - If the project is successful, what it is gonna achieve.

# overal description

- Intended users
- intended uses:
    - high level task that software will perform
    - will be used to monitor bla bla
- intended use environment
    - where and what, platform, location, IT environment
    - how they are doing now before our software?

## intended use

<aside>
💡 change of intended use is major change, and you need to apply for confirmation again.

</aside>

# non functional requirements

![Untitled](Highlights/Courses/Introduction%20to%20Medical%20Software%20from%20Yale/Untitled%2055.png)

functional req are necessary

non-functional reqs are what sells your software

user knows they need them but assume that they will be there

requirements needs to be

complete, accurate, unambiguous, traceable, testable

requirements comes from spesific use cases

### testable:

❌the system should be able to perform quickly

✅ the system should be able to perform task less than 30 seconds

### abstraction

focus on what, now how!

like describe fonts size is too detail unless you really need it, regulations wants it.
